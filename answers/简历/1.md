## 修改思路

建议保留有赞真实业务背景，把“AI Coding 落地实践、Workspace Agent、企业知识库 RAG”整合为一段更完整的“研发智能体平台”项目经历，突出你不是单点接入大模型，而是负责从工作流编排、工具接入、上下文组织、执行验证到评测闭环的 Agent 工程化建设。这样更容易把你和普通“会接 API 的前端/全栈”区分开，形成“懂业务、懂工程、懂 Agent 系统落地”的标签。

项目表述上，重点从“功能描述”升级为“系统设计”。原先简历已经有 LangGraph、RAG、MCP、Critic Agent、代码沙箱、评测链路等不错的技术点，下一步要把这些点串成一个完整闭环：需求输入解析 → 工具动态路由 → 仓库知识检索 → 代码生成/修改 → 执行验证 → Critic 评审 → 迭代修正 → 结果输出。这样写能更符合大厂对 Agent 工程、AI 应用工程、智能体平台方向的预期。

同时建议保留你已有的强量化成果，如“135 个应用接入、3.5 万条 AI 评论、500W+ 收入”等，并补齐过程型指标，例如问题定位效率、任务完成时长、检索相关度、迭代收敛轮次、回答准确率等。量化数据不一定都要写绝对值，也可以写“提升 xx%”“降低 xx%”“平均 xx 轮收敛”，但要确保能解释数据口径来源。


## 简历模版

**有赞研发智能体平台：面向代码生成与缺陷修复的 Workspace Agent**  2024.03 - 2025.03  
**AI Agent 全栈工程师 / 核心开发**

**项目描述：** 面向企业真实代码仓库建设研发智能体平台，支持基于 PRD、Figma 设计稿、Jira 缺陷等多源输入完成需求理解、仓库检索、代码生成、问题修复与结果校验。项目服务于团队 AI Coding 场景，覆盖 AI Code Review、缺陷修复辅助、页面生成等研发流程环节。  

**核心技术与方法：**

**1. 多Agent工作流设计**
  - **ReAct+Reflection+Memory：** 引入 ReAct+Reflection+Memory 机制，Agent 根据任务类型动态决策调用 Repository Search、RAG、MCP、Function Calling 与代码执行工具；通过 Reflection 模块检测并修正代码生成中的逻辑错误、上下文遗漏与仓库约束偏差；结合任务上下文 Memory 保持多轮修复与连续迭代的一致性。
  - **6Agent协作流水线：** 设计 6Agent 协作流水线，覆盖需求解析、仓库调研、上下文抽取、代码生成、执行验证、Critic 评审等环节，基于 LangGraph 实现状态图编排，支持需求→检索→生成→执行→评审的闭环迭代。
  - **智能路由：** 实现基于评审结果的智能路由机制，缺少上下文时回退检索节点，生成结果不稳定时进入修正链路，验证通过后自动完成任务输出，提升复杂研发任务的自动收敛能力。

**2. 工具(Tools)集成与优化**
  - **Web搜索：** 针对 Jira 缺陷、框架兼容性与外部依赖问题，集成 Web 搜索能力，设计 Query Expansion 与关键词拆解策略，结合相关度与时间权重过滤高质量结果，补充仓库外知识与社区解决方案。
  - **本地知识库：** 搭建企业研发知识库，沉淀仓库规范、PRD、历史迭代总结、组件说明与业务规则，采用 Milvus 向量检索 + BM25 混合召回策略，支持多 workspace 隔离与多版本知识并存查询。
  - **数据API + Text2SQL + 代码执行引擎：** 接入 Jira/代码仓库/设计稿解析等业务接口，统一封装 MCP 与 Function Calling 工具层；构建代码生成与执行引擎，支持 Python/Node 任务安全沙箱执行；结合 Text2SQL 查询任务日志、评测样本与缺陷数据，并加入白名单 SELECT 与注入防护机制。

**3. 记忆层设计**
  - **全局共享状态(ResearchState)：** 设计全局共享状态机制，统一维护任务目标、需求拆解、仓库上下文、业务规则、检索证据、生成草稿、执行结果、评审反馈等 20+ 字段，实现跨 Agent 的知识积累与状态传递。
  - **Checkpoint持久化：** 实现 Checkpoint 持久化机制，将各阶段状态快照保存至 PostgreSQL JSONB，支持长链路任务断点续传、失败回放与问题复盘。
  - **上下文Memory：** 设计上下文 Memory 模块，记录用户指令、历史修改、仓库约束、失败案例与修复策略，提升同类任务下的连续交互能力与个性化生成质量。

**4. 模块级优化**
  - **Source可信度评分：** 设计 Source 可信度评分机制，对仓库代码、官方文档、内部规范、社区资料等信息源分级打分，优先采用高可信证据，降低低质量外部内容对代码生成的干扰。
  - **对抗性评审：** 构建 Critic 对抗性评审机制，重点检测仓库规范冲突、业务逻辑错误、潜在 Bug、性能风险、安全问题、证据不足等 6 类问题，并按严重度分级处理后自动回流生成链路。
  - **SSE实时流式输出：** 实现 SSE 实时流式输出，结合异步消息队列向前端展示 Agent 当前阶段、工具调用、执行日志与评审状态，支持任务取消与进度可视化。

**量化成果：**
- 支撑 AI Code Review 接入核心业务 **135 个应用**，累计产生 **3.5 万条 AI 评论**
- 通过混合检索、上下文组织与 Critic 评审优化，问题识别相关度提升至 **85%+**
- Agent 复杂任务平均迭代收敛至 **1.5-2.5 轮**，减少人工反复补充上下文成本
- 结合代码沙箱执行与评测链路，研发问题定位和修复准备时间降低 **30%-40%**

**个人贡献：** 负责 Workspace Agent 整体架构设计与核心链路实现；主导 LangGraph 工作流编排、MCP/Function Calling 工具接入、企业知识库混合检索、代码沙箱执行、Critic 评审与评测闭环建设；推动 AI Coding 能力在真实业务研发流程中的规模化落地。



## 表达建议

1. **把“参与”改成“主导/负责具体模块”**
   - 推荐表述：主导 LangGraph 工作流编排、负责工具路由与上下文组织、设计 Critic 评审闭环。
   - 避免表述：参与方案设计、参与优化、协助接入大模型。
   - 原因：你已有较强项目深度，“参与”会削弱 ownership。

2. **项目标题要突出场景和智能体属性**
   - 推荐表述：有赞研发智能体平台 / Workspace Agent / 智能代码修复 Agent / 智能 Code Review Agent。
   - 避免表述：AI 工具接入、LLM 能力尝试、研发辅助项目。
   - 原因：招聘方更容易将你归类到 Agent 工程化与 AI 应用架构方向。

3. **量化数据优先使用已有真实结果，过程指标谨慎补充**
   - 可直接写：135 个应用、3.5 万条评论、500W+ 收入、2W+ 商家覆盖。
   - 可补充写法：问题定位时间降低 30%-40%、检索相关度 85%+、平均收敛轮次 1.5-2.5。
   - 数据来源说明：真实平台埋点、日志统计、评测集离线测试、团队阶段复盘数据。
   - 注意：如果没有稳定埋点，不要写“准确率 95%+”这类过满数字。

4. **把“工具堆砌”改成“能力闭环”**
   - 推荐表述：实现需求解析→仓库检索→代码生成→执行验证→Critic 评审→自动回流修正闭环。
   - 避免表述：使用 LangGraph、RAG、MCP、Sandbox、Prompt 优化。
   - 原因：面试官更关注系统能否稳定完成任务，而不是只会报技术名词。

5. **突出企业级约束，而不是只讲通用 Agent**
   - 推荐表述：面向真实仓库规范、多版本业务规则、workspace 隔离、代码安全执行、长链路断点恢复。
   - 避免表述：实现一个通用聊天 Agent、支持多轮对话。
   - 原因：你的优势在真实业务环境下的复杂约束处理能力。

6. **Code Review 项目要强调“风险发现”而非“自动评论”**
   - 推荐表述：识别潜在 Bug、性能风险、安全风险与高影响范围改动，辅助研发提前修复。
   - 避免表述：自动生成评论、给出代码建议。
   - 原因：前者体现业务价值，后者容易被理解成浅层套壳能力。

7. **知识库项目要突出版本化与业务规则演进**
   - 推荐表述：支持历史与当前版本共同召回，通过版本优先级与重排机制回答当前生效规则。
   - 避免表述：搭建 RAG 知识库、支持文档检索。
   - 原因：版本治理是企业知识库区别于通用 RAG 的关键亮点。

8. **面向前端/全栈岗位时保留工程实现细节**
   - 推荐补充：SSE 流式输出、React/TypeScript 前端接入、任务状态机、异常兜底、取消机制、沙箱日志可视化。
   - 原因：这能证明你不仅懂模型链路，也能完成产品化交付。
