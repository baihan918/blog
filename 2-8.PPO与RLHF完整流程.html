01 · Mental Model

先只记住这一句

Actor 原本就有一定能力；Reward 告诉它哪种回答更好；Critic 判断“这次比预期好多少”；Reference 防止它为骗分而变得奇怪；PPO 则让每次修正都不要太猛。

学生考试类比：学生先答题 → 阅卷老师给实际分 → 班主任判断是否超出预期 → 对照训练前录像检查有没有跑偏 → 教练只调整一点答题习惯。

02 · Capability Source

PPO 开始前，Actor 已经不是白纸

PPO 主要不是“灌入新知识”，而是在已有能力中，让好行为更常出现。Actor 的知识可能来自预训练，指令遵循习惯可能由 SFT 强化。

STAGE 01预训练阅读海量文本，获得语言、知识、代码和基础推理能力。
STAGE 02SFT通过“问题 + 高质量答案”示范，学会按用户要求回答。
STAGE 03Reward Model根据人类对多个回答的偏好排序，学会自动评分。
STAGE 04PPO让 Actor 自己回答、拿到奖励，再小步调整生成概率。
最简版：预训练让模型“会”，SFT 让它“会按要求做”，PPO 让它“更经常做得好”。

04 · Reward Training

Reward Model 不是凭空出现的

它通常从预训练或 SFT 模型开始，加上输出一个分数的打分头，再用人类偏好数据微调。重点不是学会绝对的“8.5 分”，而是把好回答排在差回答前面。

✓ Chosen：人类更喜欢“保持规律作息，睡前减少咖啡因和强光；如果长期失眠，建议就医。”
>
✗ Rejected：人类不喜欢“睡不着就自己加大药量，肯定有效。”
SFT 模型多次采样同一个 Prompt 用不同随机性生成多个候选回答。
人类排序标注者选出 chosen 与 rejected，不必精确打绝对分。
训练排序能力让 score(chosen) > score(rejected)，判断错了就反向传播。
PPO 时冻结Reward Model 变成自动阅卷老师，只打分，通常不再改参数。
判断边界：Actor 可能拥有 Reward Model 没有的冷门知识，但 Reward 如果无法正确判断，PPO 就可能得到错误方向。可靠边界取决于“阅卷能力”，不是单纯的“知识边界”。

    reward_score = reward_model.score(prompts, responses)   # 冻结
    ref_log_probs = reference.log_probs(prompts, responses) # 冻结

        old_log_probs, ref_log_probs
    )
    advantages, returns = compute_gae(token_rewards, values)

    update_actor_with_ppo_clip(old_log_probs, advantages)
    update_critic(values, returns)
06 · Critic & Advantage

Critic 提供一条“动态及格线”

Reward 只告诉我们实际回报；Critic 估计从当前状态继续生成，将来应该能拿多少回报。两者的差，告诉 Actor 这次表现是不是“超出预期”。

你可以拖动：同样是 8 分，如果原本只预期 5 分，就值得强化；如果原本预期 9 分，则是没有达到预期。
+3比预期好，值得强化Advantage ≈ Return − Value
Critic 怎么学

用实际 Return 当答案

初始可从 Reward Model 或 SFT 权重复制，再在 PPO 过程中不断比较“预测 Value”和“实际 Return”，缩小预测误差。

Critic 不是 Reward

一个预测，一个阅卷

Reward 通常对完整回答给分并保持冻结；Critic 对生成中的每个前缀估分，并在 PPO 中持续训练。

07 · Reference & KL

Reference 是长期安全绳

Reference 通常是 PPO 开始前 SFT 模型的冻结副本。它不主动另写一份答案，而是对 Actor 已经生成的同一串 Token 计算参考概率，以此衡量 Actor 偏离了多远。

最终奖励 = Reward 质量分 − β × KL 偏离惩罚
Reward 越高回答越符合人类偏好，提供向前的拉力。
KL 越大Actor 与初始 SFT 模型差得越多，需要扣分。
β 控制绳的松紧太小容易跑偏，太大则几乎不敢学新偏好。
Reward Hacking：如果阅卷老师偏爱长答案，Actor 可能学会堆砌废话来骗分。Reference + KL 能限制这种偏离，但不能修复一个本身就会误判的 Reward Model。

Reference Model 不等于 Old Policy

Reference Model整个 PPO 训练中固定在初始 SFT 起点，约束长期偏离。像整段旅程的出发点

≠

08 · PPO Core

PPO 实际上在改变“下次这样答”的概率

对大模型来说，状态是“Prompt + 已生成 Token”，动作是“下一个 Token”。PPO 根据 Advantage 调整这些 Token 的生成概率。

Advantage > 0

比预期好

提高这批 Token 在相似状态下被选中的概率，但一次不能提得太猛。

Advantage < 0

比预期差

降低这批 Token 被选中的概率，同样限制单次变化幅度。

概率比 r = 新 Actor 给该 Token 的概率 ÷ Old Policy 给它的概率
r = 1.0新旧策略对这个 Token 的看法没有变。
r = 1.1新 Actor 让它的出现概率提高了约 10%。
Clip 如 [0.8, 1.2]超出区间后不再鼓励继续猛改，保持训练稳定。
开车类比：方向偏左时，向右修一点；不会因为一次偏左就猛打一圈方向盘。这就是 Proximal——新策略始终靠近旧策略。
09 · Boundaries

这套流程能做什么，不擅长什么

擅长

对齐已有能力的使用方式

  • 更遵循指令
  • 更有帮助且表达清楚
  • 更安全、少生成危险内容
  • 让好回答从“偶尔出现”变成“稳定出现”
不擅长

凭一个分数灌入大量新知识

  • Actor 完全不会时，Reward 只说“不好”还不够
  • 阅卷标准有漏洞时会产生 Reward Hacking
  • 专业领域超出 Reward 判断能力时会误导训练
  • 新知识更适合预训练、SFT、RAG 或工具
常见误解更准确的说法
Reward Model 把知识教给 ActorReward 主要给出方向，不直接给标准答案；PPO 强化 Actor 能生成的好行为。
Critic 也是另一个评分老师Critic 学的是“预测未来 Return”，用于计算超出预期多少，它会在 PPO 中更新。
Reference 和 Old Policy 是同一个模型Reference 是长期固定的 SFT 锚点；Old Policy 是每批采样时 Actor 的临时快照。
Clip 强行把所有概率截到 0.8～1.2Clip 主要是截断“过度改变带来的优化收益”，并非简单修改每个输出概率。
10 · Interview Answer

用一段话把 PPO 讲完

如果面试官问“RLHF 中 PPO 的流程”，可以按下面顺序回答。

可直接复述：Actor 通常由 SFT 模型初始化，先对 Prompt 采样生成回答。冻结的 Reward Model 给完整回答打偏好分，冻结的 Reference Model 用来计算 KL 惩罚，防止 Actor 长期偏离 SFT 起点。Critic 估计每个生成状态的未来回报，结合实际 Return 得到 Advantage。PPO 用新旧策略概率比和 Clip 目标更新 Actor，限制单次更新幅度；同时用 Return 训练 Critic。然后用新 Actor 重新采样，循环进行。

最终心智模型：Reward 管方向，Critic 管相对惊喜，Reference 管长期偏离，Old Policy + Clip 管单次步子，Actor 才是最终被训练得更会回答的模型。

11 · GRPO

GRPO：不找 Critic 估分，改成同题组内比较

GRPO 全称 Group Relative Policy Optimization。它仍是在线强化学习：Actor 先对同一道题生成一组回答，每份回答拿到奖励，然后根据“高于还是低于组内平均”计算 Advantage。

学生类比：PPO 是“学生的实际分和班主任 Critic 的预测分比”；GRPO 是“学生对同一道题写多份答案，彼此比较”。

用四份答案看懂“组内相对”

回答 A2低于平均 → 削弱

回答 C8高于平均 → 强化
回答 D6高于平均 → 强化
组内平均分 = 5　　 Aᵢ ≈ (rᵢ − 5) ÷ 组内标准差
高于组内平均对应回答的相对 Advantage 为正，提高其生成概率。
低于组内平均相对 Advantage 为负，降低其生成概率。
整组都一样标准差接近 0，组内没有谁更好，学习信号很弱。

GRPO 的 Reward 可以不是模型

可验证任务

直接用规则打分

数学题核对最终答案，代码运行单元测试，格式通过正则检查。这时不需要预先微调 Reward Model，但仍然必须有能产生分数的 Reward Function。

主观任务

仍可能需要 Reward Model

“是否有同理心”、“文章是否优美”很难用硬规则衡量，可使用偏好模型、LLM Judge、人工评分或混合奖励。GRPO 只规定如何比较奖励，不限定奖励必须从哪里来。

别误解“不需要预训练”：可以不训练 Reward Model，但 Actor 通常仍是已经大规模预训练的语言模型。规则奖励也不等于没有监督：标准答案、测试用例和验证程序就是监督来源。

12 · DPO

DPO：不现场考试，直接学“A 比 B 好”

DPO 全称 Direct Preference Optimization。它把现成的 chosen / rejected 偏好对直接变成训练损失：让 Actor 相对于 Reference 更偏爱 chosen，更不偏爱 rejected。训练中不需要 Reward Model、Critic 或在线 rollout。

✓ chosen“保持规律作息，睡前减少咖啡因；若长期失眠建议就医。”
>
✗ rejected“睡不着就自己加大药量，肯定有效。”
离线偏好数据Prompt + chosen + rejected
→
Actor计算两个回答的概率
+
Reference提供训练前的概率基准
→
偏好差值chosen 提升 − rejected 提升
→
DPO Loss只更新 Actor
SFT

只看到好答案

数据是 Prompt → chosen，目标是提高 chosen 的生成概率。模型并不知道对照组中哪种回答不受偏好。

DPO

同时看到好与差

数据是 Prompt + chosen > rejected，目标是让 Actor 相对 Reference 更明确地选 chosen，而不是无限制把一个答案概率推高。

DPO 想放大的信号 = chosen 相对 Reference 的提升 − rejected 相对 Reference 的提升
没有显式 Reward Model偏好直接作用在 Actor 的概率差上，不需要先把偏好学成打分模型。
没有在线探索训练时只消化已有偏好对，不会像 GRPO 那样边生成边验证新解法。
β 控制偏好强度它影响对偏好差的敏感度与相对 Reference 的保守程度，具体语义要以实现为准。
优点

像普通微调一样简洁

  • 不训练 Reward Model 和 Critic
  • 不需要在线生成环境
  • 显存、工程和调参成本较低
  • 适合已有高质量偏好对的场景
限制

上限受离线偏好数据约束

  • 错误标注会被直接学进 Actor
  • 未覆盖场景很难凭空获得好的偏好信号
  • 不像在线 RL 能够通过验证器持续探索
  • chosen / rejected 差异不合理会学到偏差
