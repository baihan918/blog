1. 输入 x 到底是什么

Attention 接收到的 x 通常不是原始字符串。

原始文本会先经过以下步骤：

text
原始文本
  ↓
Tokenizer
  ↓
Token ID
  ↓
Embedding
  ↓
输入张量 x

例如原始句子：

text
我喜欢吃苹果

Tokenizer 可能把它拆成：

text
["我", "喜欢", "吃", "苹果"]

这里一共有 4 个 Token。

Embedding 层会把每个 Token 转成一个向量。假设每个 Token 用 8 个数字表示：

text
“我”：
[0.2, 0.8, 0.1, 0.4, 0.7, 0.3, 0.5, 0.9]

“喜欢”：
[0.6, 0.2, 0.7, 0.1, 0.3, 0.8, 0.4, 0.5]

“吃”：
[0.4, 0.9, 0.2, 0.6, 0.1, 0.5, 0.7, 0.3]

“苹果”：
[0.8, 0.3, 0.6, 0.2, 0.9, 0.1, 0.4, 0.7]

这 4 个 Token 向量组合起来，就构成一句话的输入。

在 PyTorch 中，x 通常是一个三维张量：

python
x.shape == [B, L, D]

三个维度分别表示：

  • B：Batch Size，一次处理多少条样本
  • L：Sequence Length，每条样本有多少个 Token
  • D：Hidden Size，每个 Token 使用多少个数字表示

例如：

python
x.shape == [2, 4, 8]

含义是：

text
一次处理 2 句话；
每句话有 4 个 Token；
每个 Token 是一个 8 维向量。

可以展开理解为：

text
Batch 0
  Token 0 -> 8 个数字
  Token 1 -> 8 个数字
  Token 2 -> 8 个数字
  Token 3 -> 8 个数字

Batch 1
  Token 0 -> 8 个数字
  Token 1 -> 8 个数字
  Token 2 -> 8 个数字
  Token 3 -> 8 个数字

x 中每个 Token 已经有了向量表示，但还没有区分以下三种角色：

text
Query：我想寻找什么
Key：别人可以怎样找到我
Value：我真正可以提供什么信息

Attention 接下来会把同一个 x 分别投影为 Q、K、V。

2. q = self.q_proj(x)

代码：

python
q = self.q_proj(x)

这一行把输入 x 转换成 Query，也就是查询向量 Q。

2.1 self.q_proj 是什么

self.q_proj 通常在类的初始化方法中定义：

python
self.q_proj = nn.Linear(d_model, d_model)

例如：

python
self.q_proj = nn.Linear(8, 8)

它表示：

text
输入维度：8
输出维度：8

这个线性层内部包含两部分可训练参数：

text
权重矩阵 Wq
偏置向量 bq

计算过程可以表示为：

text
Q = XWq + bq

因此：

python
q = self.q_proj(x)

可以近似理解为：

python
q = x @ Wq + bq

实际代码不需要手动写 Wq 和 bq，因为它们由 nn.Linear 自动创建和维护。

2.2 Query 的含义

Query 可以理解为：

当前 Token 想寻找什么信息？

每个 Token 都会生成自己的 Query。

例如句子：

text
小明把苹果给了小红，因为她饿了

当模型处理“她”时，“她”的 Query 可以抽象理解为：

text
我应该指代前面的哪个人物？

当模型处理“饿”时，“饿”的 Query 可以抽象理解为：

text
是谁处于饥饿状态？

模型内部并不存在这样的中文句子。

内部只有一组数字向量，但训练会让 Query 向量逐渐具备这种“查询信息”的能力。

2.3 为什么不能直接使用 x 作为 Query

输入 x 是 Token 的通用表示。

如果直接拿 x 做所有工作，那么模型只能用同一种表示完成：

text
查询
匹配
信息传递

增加一层：

python
self.q_proj

相当于让模型单独学习：

输入 x 应该如何变换，才能更适合表达“我要找什么”。

Wq 是可训练参数。

训练过程中，反向传播会不断调整 Wq，让生成的 Query 更适合当前任务。

2.4 Q 的 Shape

假设输入：

python
x.shape == [B, L, D]

线性层定义为：

python
self.q_proj = nn.Linear(D, D)

那么输出：

python
q.shape == [B, L, D]

例如：

text
x.shape = [2, 4, 8]
q.shape = [2, 4, 8]

Batch 数量没有变化。

Token 数量没有变化。

每个 Token 的向量维度也没有变化。

变化的是每个 Token 向量内部的数值和它承担的语义角色。

可以理解为：

text
Shape 没变，但表示方式变了。

2.5 nn.Linear 如何处理三维张量

nn.Linear 不只可以处理二维矩阵。

它会自动对输入张量的最后一个维度执行线性变换。

假设：

python
x.shape == [2, 4, 8]
self.q_proj = nn.Linear(8, 8)

PyTorch 会对 2 个 Batch 中的 4 个 Token 分别执行同一个线性变换。

可以近似理解为：

python
for batch_index in range(2):
    for token_index in range(4):
        q[batch_index, token_index] = (
            x[batch_index, token_index] @ Wq + bq
        )

所有 Token 共用同一组 Wq 和 bq。

这意味着模型不是给每个 Token 单独训练一套参数，而是学习一套通用的 Query 投影规则。

3. k = self.k_proj(x)

代码：

python
k = self.k_proj(x)

这一行把输入 x 转换成 Key，也就是索引向量 K。

3.1 self.k_proj 是什么

它也是一个线性层：

python
self.k_proj = nn.Linear(d_model, d_model)

计算过程：

text
K = XWk + bk

其中：

  • Wk：Key 的权重矩阵
  • bk：Key 的偏置
  • K：生成的 Key 向量

需要注意：

text
Wq 和 Wk 不是同一组参数。

也就是说：

text
Wq != Wk

Query 和 Key 都来自 x，但因为使用不同参数，最终表示也不同。

3.2 Key 的含义

Key 可以理解为：

当前 Token 有哪些特征，别人可以通过什么方式找到我？

仍然使用这个句子：

text
小明把苹果给了小红，因为她饿了

可以把不同 Token 的 Key 抽象理解为：

text
“小明”：
人物、男性、主语

“苹果”：
物品、食物、被传递对象

“小红”：
人物、女性、接收者

“她”：
代词、女性指代

模型内部不会真的保存这些中文标签。

Key 仍然是一串数字。

只是训练完成后，这些数字会编码出某些可被查询和匹配的特征。

3.3 Query 和 Key 如何配合

Query 表达：

text
我想找什么？

Key 表达：

text
我有什么特征？

模型会把一个 Token 的 Query 和所有 Token 的 Key 做比较。

例如“她”的 Query 会分别和下面这些 Key 比较：

text
“小明”的 Key
“苹果”的 Key
“小红”的 Key
“因为”的 Key
“她”的 Key
“饿”的 Key

假设“她”的 Query 与“小红”的 Key 最匹配，那么“她”就会对“小红”分配更高的注意力权重。

3.4 K 的 Shape

如果：

python
x.shape == [B, L, D]

并且：

python
self.k_proj = nn.Linear(D, D)

那么：

python
k.shape == [B, L, D]

例如：

text
x.shape = [2, 4, 8]
k.shape = [2, 4, 8]

Shape 没有变化，但每个向量被重新编码成适合“被查询”的表示。

4. v = self.v_proj(x)

代码：

python
v = self.v_proj(x)

这一行把输入 x 转换成 Value，也就是真正携带信息的向量 V。

4.1 self.v_proj 是什么

它同样是一个线性层：

python
self.v_proj = nn.Linear(d_model, d_model)

计算过程：

text
V = XWv + bv

其中：

  • Wv：Value 的权重矩阵
  • bv：Value 的偏置
  • V：后续真正参与信息汇总的向量

三组参数彼此不同：

text
Wq != Wk
Wq != Wv
Wk != Wv

4.2 Value 的含义

Value 可以理解为：

当前 Token 真正可以提供给其他 Token 的信息。

Q 和 K 主要负责计算：

text
谁应该关注谁

V 负责提供：

text
关注之后真正拿走什么信息

可以使用搜索引擎类比：

text
Q：用户输入的搜索词
K：网页标题、关键词、标签
V：网页正文内容

搜索系统先用 Q 和 K 匹配。

匹配完成后，真正需要读取的是 V。

Attention 也是一样：

text
Q 和 K 负责决定关注关系；
V 负责提供被汇总的信息。

4.3 为什么最终不是 weights @ k

Key 只负责匹配。

它类似目录、索引或标签。

真正需要传递给其他 Token 的内容保存在 Value 中。

因此代码写的是：

python
output = weights @ v

而不是：

python
output = weights @ k

如果继续用搜索系统类比：

text
你先通过标题和关键词找到网页，
最终读取的是网页正文，
而不是把所有网页标题拼接起来。

4.4 V 的 Shape

如果：

python
x.shape == [B, L, D]

并且：

python
self.v_proj = nn.Linear(D, D)

那么：

python
v.shape == [B, L, D]

例如：

text
v.shape = [2, 4, 8]

5. 为什么 Q、K、V 都来自同一个 x

代码：

python
q = self.q_proj(x)
k = self.k_proj(x)
v = self.v_proj(x)

三者都来自同一个输入 x，这是因为这里实现的是 Self-Attention。

Self-Attention 的意思是：

一个序列内部的所有 Token 相互查看、相互匹配、相互传递信息。

同一个 Token 同时扮演三种角色：

text
Q：我想寻找什么
K：别人可以怎样找到我
V：我真正可以提供什么

虽然都来自同一个 x，但是经过三组不同参数：

python
Q = X @ Wq
K = X @ Wk
V = X @ Wv

所以最终数值不同。

可以把它类比成同一个人在会议中：

text
他可以提出问题；
他可以被别人点名；
他可以提供自己的意见。

同一个人，但角色不同。

6. scores = q @ k.transpose(-2, -1)

代码：

python
scores = q @ k.transpose(-2, -1)

这一行的作用是：

计算每个 Query 和所有 Key 之间的相关性分数。

这是 Attention 中最核心的步骤之一。

6.1 @ 是什么

Python 中：

python
@

表示矩阵乘法。

例如：

python
a @ b

通常等价于：

python
torch.matmul(a, b)

因此：

python
scores = q @ k.transpose(-2, -1)

也可以写成：

python
scores = torch.matmul(q, k.transpose(-2, -1))

6.2 为什么不能直接写 q @ k

假设：

text
q.shape = [B, L, D]
k.shape = [B, L, D]

只看最后两个维度：

text
q: [L, D]
k: [L, D]

矩阵乘法要求：

text
[A, B] @ [B, C]

也就是前一个矩阵的最后一维，必须等于后一个矩阵的倒数第二维。

但直接相乘时：

text
[L, D] @ [L, D]

中间两个维度是：

text
D 和 L

通常不相等，所以不能直接相乘。

因此需要先转置 K。

6.3 k.transpose(-2, -1) 是什么

假设：

python
k.shape == [B, L, D]

这里：

text
-1 表示最后一个维度 D
-2 表示倒数第二个维度 L

执行：

python
k.transpose(-2, -1)

就是交换 L 和 D。

原来：

text
[B, L, D]

转置后：

text
[B, D, L]

例如：

text
原来：
[2, 4, 8]

转置后：
[2, 8, 4]

Batch 维度没有变化。

只交换最后两个维度。

6.4 为什么使用负数索引

也可以写成：

python
k.transpose(1, 2)

对于三维张量 [B, L, D]，这同样可以交换 L 和 D。

但是：

python
k.transpose(-2, -1)

更通用。

因为在 Multi-Head Attention 中，张量可能是：

text
[B, H, L, D]

其中：

  • B：Batch
  • H：Head 数量
  • L：Token 数量
  • D：每个 Head 的维度

此时依然只需要交换最后两个维度：

text
[B, H, L, D]
        ↓
[B, H, D, L]

所以使用：

python
transpose(-2, -1)

不需要关心前面有多少维。

6.5 Shape 如何变化

假设：

text
q.shape = [B, L, D]
k.shape = [B, L, D]

K 转置以后：

text
k.transpose(-2, -1).shape = [B, D, L]

矩阵乘法：

text
[B, L, D] @ [B, D, L]

中间的 D 被消掉，结果是：

text
[B, L, L]

因此：

python
scores.shape == [B, L, L]

6.6 [B, L, L] 表示什么

假设一句话有 4 个 Token：

text
我  喜欢  吃  苹果

那么对于每句话，scores 是一个 4 × 4 的矩阵：

text
          Key
          我    喜欢    吃    苹果
Query 我   ?      ?      ?      ?
Query 喜欢 ?      ?      ?      ?
Query 吃   ?      ?      ?      ?
Query 苹果 ?      ?      ?      ?

行代表 Query。

列代表 Key。

例如：

python
scores[0, 2, 3]

假设：

  • 第一个索引 0：Batch 0
  • 第二个索引 2：第 3 个 Token“吃”的 Query
  • 第三个索引 3：第 4 个 Token“苹果”的 Key

那么：

python
scores[0, 2, 3]

表示：

Batch 0 中，“吃”对“苹果”的原始相关性分数。

6.7 Q 和 K 的点积如何计算

假设一个 Query 向量是：

text
q = [1, 2]

一个 Key 向量是：

text
k = [3, 4]

点积计算：

text
1 × 3 + 2 × 4
= 3 + 8
= 11

这个结果 11 就是二者的匹配分数。

如果另一个 Key 是：

text
k2 = [-1, 0]

那么：

text
q · k2
= 1 × (-1) + 2 × 0
= -1

相对来说：

text
q 与 k 的匹配程度更高；
q 与 k2 的匹配程度更低。

在真实模型里，向量维度可能是 64、128，甚至更大。

点积会把所有维度的匹配情况累加成一个标量分数。

6.8 为什么点积可以表示相似度

当两个向量方向比较接近时，点积通常较大。

当两个向量方向差异较大时，点积较小。

当两个向量方向相反时，点积可能为负数。

因此模型可以通过训练，让需要互相关注的 Query 和 Key 在向量空间中更加匹配。

需要注意：

Attention 中的 Q 和 K 都是模型学习出来的表示，不是固定的原始 Embedding。

所以模型可以自己学习什么样的特征组合应该得到更高的分数。

7. scores = scores / math.sqrt(q.size(-1))

代码：

python
scores = scores / math.sqrt(q.size(-1))

这一行的作用是：

对 Q 和 K 的点积分数进行缩放，避免分数随着向量维度增加而变得过大。

这一步对应 Scaled Dot-Product Attention 中的“Scaled”。

7.1 q.size(-1) 是什么

假设：

python
q.shape == [B, L, D]

那么：

python
q.size(-1)

表示读取最后一个维度的大小，也就是：

text
D

例如：

python
q.shape == [2, 4, 64]

那么：

python
q.size(-1) == 64

在 Attention 公式中，这个维度通常写成：

text
dₖ

代表 Key 或 Query 的向量维度。

7.2 math.sqrt(q.size(-1))

如果：

python
q.size(-1) == 64

那么：

python
math.sqrt(q.size(-1))

就是：

text
√64 = 8

所以：

python
scores = scores / math.sqrt(q.size(-1))

相当于：

python
scores = scores / 8

7.3 为什么维度越大，点积越容易变大

Q 和 K 的点积是多个数字乘积的累加。

假设维度是 2：

text
q · k
= q1k1 + q2k2

假设维度是 64：

text
q · k
= q1k1 + q2k2 + ... + q64k64

维度越多，累加项越多。

即使每一项不是很大，最终结果的绝对值也容易变大。

因此，当 dₖ 很大时，scores 中可能出现较大的正数和负数。

7.4 分数太大为什么有问题

下一步会执行 Softmax。

假设原始分数是：

text
[2, 5, 30]

Softmax 需要计算指数：

text
e²
e⁵
e³⁰

因为：

text
e³⁰

远大于前两个数字，所以最终权重会非常接近：

text
[0, 0, 1]

模型几乎把全部注意力都分给第三个位置。

如果这种极端情况在训练早期频繁出现，会导致：

text
Softmax 输出过于尖锐；
部分位置的梯度非常小；
参数更新困难；
训练不稳定。

7.5 除以 √dₖ 后发生什么

仍然假设：

text
scores = [2, 5, 30]
dₖ = 64
√dₖ = 8

缩放后：

text
[2/8, 5/8, 30/8]
=
[0.25, 0.625, 3.75]

这些数仍然保留原来的大小关系：

text
3.75 最大；
0.625 第二；
0.25 最小。

但差距没有原来那么极端。

Softmax 得到的分布会更平滑。

7.6 为什么是除以 √dₖ，而不是除以 dₖ

如果 Q 和 K 的每个元素都近似满足：

text
均值为 0；
方差为 1。

那么点积：

text
Q · K

的方差会随着 dₖ 增长。

大致可以理解为：

text
点积方差 ≈ dₖ

标准差大约是：

text
√dₖ

所以除以：

text
√dₖ

可以把数值尺度拉回相对稳定的范围。

作为 AI 应用工程师，重点需要理解：

text
向量维度越大，点积分数越容易变大；
除以 √dₖ 是为了控制数值范围；
这样 Softmax 不会过早进入极端状态；
训练会更加稳定。

不需要手动推导概率分布和方差公式。

8. weights = torch.softmax(scores, dim=-1)

代码：

python
weights = torch.softmax(scores, dim=-1)

这一行的作用是：

把原始相关性分数转换成 Attention 权重。

8.1 scores 还不是权重

假设某个 Token 对所有 Token 的分数是：

text
[2.0, 1.0, -1.0, 3.0]

这些值可能：

text
大于 1；
小于 0；
总和不等于 1。

它们只是原始匹配分数，不能直接理解为比例。

Softmax 会把它们转换成类似：

text
[0.24, 0.09, 0.01, 0.66]

转换后：

text
每个值都在 0 到 1 之间；
所有值加起来等于 1。

因此可以把它们理解为注意力分配比例。

8.2 Softmax 的计算公式

对于一组分数：

text
z1, z2, ..., zn

Softmax 对第 i 个分数的计算是：

text
softmax(zi)
=
exp(zi)
/
Σ exp(zj)

例如分数：

text
[1, 2]

先计算指数：

text
e¹ ≈ 2.718
e² ≈ 7.389

总和：

text
2.718 + 7.389 = 10.107

最终权重：

text
第一个位置：
2.718 / 10.107 ≈ 0.269

第二个位置：
7.389 / 10.107 ≈ 0.731

得到：

text
[0.269, 0.731]

总和：

text
0.269 + 0.731 = 1

8.3 dim=-1 是什么意思

scores 的 Shape 是：

text
[B, L, L]

最后一个维度表示：

当前 Query 可以关注的所有 Key。

例如：

text
scores[0, 2, :]

表示：

Batch 0 中，第 3 个 Token 对所有 Token 的相关性分数。

所以需要沿最后一个维度做 Softmax：

python
torch.softmax(scores, dim=-1)

这会让每一行的权重和等于 1。

8.4 一个 4 × 4 的例子

假设一句话有 4 个 Token：

text
我  喜欢  吃  苹果

某个 scores 矩阵可能是：

text
          我    喜欢    吃    苹果
我        2.0   1.0   0.5   0.2
喜欢      0.8   2.1   1.2   0.7
吃        0.2   0.6   1.0   2.5
苹果      0.3   0.4   1.4   2.0

Softmax 按行计算。

对于“吃”这一行：

text
[0.2, 0.6, 1.0, 2.5]

转换后可能得到：

text
[0.07, 0.10, 0.15, 0.68]

这表示：

text
“吃”关注“我”：7%
“吃”关注“喜欢”：10%
“吃”关注“吃”：15%
“吃”关注“苹果”：68%

可以看到，“吃”最关注“苹果”。

8.5 为什么需要 Softmax

如果直接使用原始分数：

text
[0.2, 0.6, 1.0, 2.5]

这些数没有统一尺度。

不同 Query 的分数范围可能完全不同。

Softmax 把每一行转换成一个标准化分布：

text
所有权重都是正数；
所有权重总和等于 1；
分数更高的位置获得更大权重。

这样下一步可以使用这些权重对 V 做加权求和。

8.6 Softmax 不代表真实概率

Attention 权重看起来像概率，因为它们：

text
位于 0 到 1；
总和为 1。

但更准确的说法是：

它们是归一化后的注意力分配权重。

它们表示模型当前把多少信息读取比例分配给不同 Token。

不能简单把它理解为语言学上的真实概率或因果解释。

9. output = weights @ v

代码：

python
output = weights @ v

这一行的作用是：

使用 Attention 权重，对所有 Token 的 Value 做加权求和。

这是 Attention 真正完成上下文信息融合的步骤。

9.1 Shape 如何变化

已知：

text
weights.shape = [B, L, L]
v.shape       = [B, L, D]

矩阵乘法：

text
[B, L, L] @ [B, L, D]

中间的 L 被消掉，结果是：

text
[B, L, D]

因此：

python
output.shape == [B, L, D]

例如：

text
weights.shape = [2, 4, 4]
v.shape       = [2, 4, 8]

output.shape  = [2, 4, 8]

输出与输入的 Shape 相同。

但是输出中每个 Token 的向量，已经融合了其他 Token 的信息。

9.2 weights @ v 到底算了什么

假设当前 Token 对 4 个 Token 的权重是：

text
[0.1, 0.2, 0.1, 0.6]

对应 4 个 Value：

text
V1
V2
V3
V4

那么当前 Token 的输出就是：

text
output
=
0.1 × V1
+
0.2 × V2
+
0.1 × V3
+
0.6 × V4

也就是说：

text
从 V1 读取 10% 的信息；
从 V2 读取 20% 的信息；
从 V3 读取 10% 的信息；
从 V4 读取 60% 的信息。

最终把这些信息相加，形成新的上下文向量。

9.3 使用二维向量做具体计算

假设有 3 个 Token，它们的 Value 是：

text
V1 = [1, 0]
V2 = [0, 2]
V3 = [3, 1]

某个 Query 对这三个 Token 的 Attention 权重是：

text
[0.2, 0.3, 0.5]

那么输出：

text
output
=
0.2 × [1, 0]
+
0.3 × [0, 2]
+
0.5 × [3, 1]

分别计算：

text
0.2 × [1, 0]
=
[0.2, 0]

0.3 × [0, 2]
=
[0, 0.6]

0.5 × [3, 1]
=
[1.5, 0.5]

相加：

text
[0.2, 0]

[0, 0.6]
+
[1.5, 0.5]
=
[1.7, 1.1]

所以当前 Token 的输出向量是：

text
[1.7, 1.1]

这个输出同时融合了三个 Token 的信息，但不同 Token 的贡献比例不同。

9.4 为什么输出维度仍然是 D

权重矩阵：

text
[B, L, L]

只负责决定：

text
每个 Query 应该从每个 Value 读取多少信息。

Value 的每个 Token 仍然是 D 维向量：

text
[B, L, D]

加权求和只是把多个 D 维向量混合起来。

所以结果仍然是 D 维向量：

text
[B, L, D]

9.5 输出和输入有什么不同

输入：

text
x[i]

主要是第 i 个 Token 自己的基础表示。

输出：

text
output[i]

是第 i 个 Token 根据 Attention 权重，从整个序列读取信息后的上下文表示。

例如原始 Token：

text
“苹果”

输入向量主要表达“苹果”本身。

经过 Attention 后，它可能融合：

text
“吃”的动作信息；
“喜欢”的情感信息；
句子中主语“我”的信息。

因此输出不再只是孤立 Token 的表示，而是：

带有上下文信息的 Token 表示。

13. 这段代码中容易混淆的细节

13.1 Q、K、V 不是三个不同输入

在 Self-Attention 中：

python
q = self.q_proj(x)
k = self.k_proj(x)
v = self.v_proj(x)

Q、K、V 都来自同一个 x。

区别在于它们经过不同的线性层。

13.2 Q、K、V 不是固定规则生成的

q_proj、k_proj、v_proj 中的参数都会训练。

模型不是由程序员提前规定：

text
哪个 Token 应该关注哪个 Token。

而是通过训练数据自动学习这些关系。

13.3 scores 不是最终权重

python
scores = q @ k.transpose(-2, -1)

得到的是原始匹配分数。

它们可能为负，也可能很大。

经过：

python
weights = torch.softmax(scores, dim=-1)

之后才得到 Attention 权重。

13.4 权重矩阵的行和列不要看反

对于：

text
weights.shape = [B, L, L]

通常可以理解为：

text
行：Query，也就是“谁在看”
列：Key，也就是“正在看谁”

例如：

python
weights[0, 2, 3]

表示：

text
Batch 0 中，
第 3 个 Token
对第 4 个 Token
分配了多少注意力。

13.5 输出不是把 Token 数量压缩成一个

输入 Shape：

text
[B, L, D]

输出 Shape：

text
[B, L, D]

每个 Token 都会得到一个新的上下文向量。

Attention 并不是默认把整句话压缩成一个向量。

13.6 q.size(-1) 在 Multi-Head Attention 中通常是 head_dim

在单头示例中：

text
q.size(-1) = d_model

在多头 Attention 中，Q 通常会被拆成：

text
[B, H, L, head_dim]

这时：

python

获取的是：

text
head_dim

缩放因子应当是：

text
√head_dim

而不是整个 d_model。

14. 加上因果 Mask 后代码的位置

生成式模型不能看到未来 Token。

例如序列：

text

在预测“喜欢”后面的内容时，当前 Token 不能提前读取“吃”和“苹果”。

因果 Mask 一般加在 Softmax 之前：

python
scores = q @ k.transpose(-2, -1)
scores = scores / math.sqrt(q.size(-1))

scores = scores.masked_fill(~mask, float("-inf"))

weights = torch.softmax(scores, dim=-1)
output = weights @ v

Mask 可能是：

text
[
  [1, 0, 0, 0],
  [1, 1, 0, 0],
  [1, 1, 1, 0],
  [1, 1, 1, 1]
]

其中：

text
1：允许关注
0：禁止关注

被禁止的位置会被填成：

text
负无穷

因为：

text
softmax(-∞) = 0

所以这些位置最终不会获得注意力权重。

15. 对应的完整 Single-Head Self-Attention 代码

python
import math

import torch
from torch import Tensor, nn


class SingleHeadSelfAttention(nn.Module):
    def __init__(self, d_model: int) -> None:
        super().__init__()

        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)
        self.out_proj = nn.Linear(d_model, d_model)

    def forward(
        self,
        x: Tensor,
        mask: Tensor | None = None,
    ) -> tuple[Tensor, Tensor]:
        q = self.q_proj(x)
        k = self.k_proj(x)
        v = self.v_proj(x)

        scores = q @ k.transpose(-2, -1)
        scores = scores / math.sqrt(q.size(-1))

        if mask is not None:
            scores = scores.masked_fill(~mask, float("-inf"))

        weights = torch.softmax(scores, dim=-1)

        context = weights @ v

        output = self.out_proj(context)

        return output, weights

其中：

python
context = weights @ v

是 Attention 汇总后的上下文。

随后：

python
output = self.out_proj(context)

再通过一个输出线性层，把上下文映射回模型需要的表示空间。

out_proj 在完整 Attention 中通常存在，但最核心的 Attention 计算仍然是：

python
scores = q @ k.transpose(-2, -1)
scores = scores / math.sqrt(q.size(-1))
weights = torch.softmax(scores, dim=-1)
context = weights @ v
