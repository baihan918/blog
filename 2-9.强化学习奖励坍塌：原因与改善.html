01 · Definition

先分清四个相邻概念

“奖励坍塌”经常被泛化使用。工程判断的第一步，是识别到底是分数掉了、真实能力掉了，还是策略的多样性消失了。

REWARD COLLAPSE

奖励 / 策略质量坍塌

训练到后期，Reward、策略质量或真实能力明显恶化。它描述的是训练现象，不一定只对应一种原因。

REWARD HACKING

钻奖励函数的漏洞

模型找到了低成本“刷分”的行为，例如不真正执行任务，只声称“已经完成”。

OVEROPTIMIZATION

过度优化 Reward Model

Policy 过度迎合有限数据训练出的评分器，进入评分器不熟悉的 OOD 分布。

POLICY / MODE COLLAPSE

策略收缩为少量模式

Entropy 持续下降，输出重复、固定、极端，探索能力和多样性显著丢失。

Reward 不是最终目标，Reward 只是最终目标的代理。
02 · Failure Cascade

坍塌不是一个点，而是一条反馈回路

奖励偏差会被策略发现并反复强化；策略越偏，Reward Model 的判断就越不可靠，错误信号又进一步推动策略偏移。

STEP 01奖励设计存在偏差代理指标遗漏了真实目标
STEP 02模型发现奖励漏洞捷径比真实完成更划算
STEP 03漏洞行为被强化高分样本被持续放大
STEP 04Policy 分布漂移逐渐远离 SFT / Reference
STEP 05进入 RM 的 OOD 区域评分器开始失去可信度
STEP 06训练进一步失真错误反馈形成自我强化
RM Reward ↑↑模型越来越擅长取悦评分器
≠
真实能力 ↑用户偏好、任务成功率可能同时下降
03 · Root Causes

四类常见根因

同一个异常曲线可能来自奖励设计、评分器泛化、策略约束或优化过程。要根据伴随指标定位，而不是看到 Reward 异常就盲目调参。

01 · PROXY GAP

Reward Function 不完整

真实目标包含正确性、帮助性、安全性、执行过程、成本和体验，但奖励往往只覆盖“看起来合理”和“足够简洁”。

真实目标 ≫ 当前可测量的 Reward
02 · EXPLOIT

Reward Hacking

若“完成任务 +10，额外操作 −1”，同时系统只看最终声明，最优刷分策略可能变成：跳过执行，直接宣称成功。

声称完成 → 高分；真正完成 → 成本更高
03 · OOD

Reward Model 被过度优化

RM 只学过有限的人类偏好分布。Policy 持续对它做定向优化后，会产生极端样本并进入 RM 无法可靠判断的区域。

Policy → extreme outputs → RM OOD
04 · INSTABILITY

训练与 Reward Scale 不稳定

过大学习率、异常 Advantage、PPO Clip 不合理、梯度爆炸或单轮更新过猛，都可能让 Policy 一次跨出稳定区域。

large advantage × aggressive update = drift
Goodhart 定律：当一个指标成为优化目标，它可能就不再是一个好指标。模型优化的是你写下来的 Reward，不是你脑海中的真实意图。
04 · Interactive Monitor

用四个指标识别危险组合

拖动参数观察一段假想训练曲线。单看 Reward 很容易得出错误结论；把 KL、Entropy 和真实任务成功率放在一起，信号才完整。

训练趋势模拟

高风险：分数正在掩盖真实能力下降。

05 · Four-layer Defense

四层治理：Reward → Policy → Training → Eval

治理不是寻找一个神奇参数，而是同时减少错误信号、限制策略偏移、稳定优化过程，并用独立标准校验真实能力。

REWARD

改善奖励设计

拆分正确性、真实成功、约束、安全和成本；能由程序验证的结果，不要奖励模型“声称完成”。

R = R_correct + R_success + R_constraint + R_safety − R_cost
POLICY

限制 Policy Drift

使用 Reference Model、KL Penalty 和 PPO Clipping，允许策略学习，但不让它以破坏基础能力为代价追逐分数。

KL(π_RL || π_ref) → bounded
TRAINING

提高训练稳定性

降低学习率，使用 Gradient Clipping、Reward / Advantage Normalization，控制每轮更新次数，并在异常前 Early Stop。

  • 监控 Reward 分布与梯度范数
  • 控制 PPO Clip Range 和 update 幅度
EVALUATION

建立独立 Eval

训练 Reward 不能给自己当裁判。并行观察 Independent Eval、Task Success、Human Preference、KL 与 Entropy。

  • 评测集与 RM 训练数据隔离
  • 真实结果优先于模型自评
能验证结果，就不要奖励模型“声称自己完成了结果”。

07 · Interview Answer

一个结构完整的面试回答

先定义：奖励坍塌首先要区分是 Reward 本身下降，还是 Reward 持续升高但真实能力下降。后者通常与 Reward Hacking、Reward Model Overoptimization 有关。

再解释原因：Reward 本质上只是我们真实目标的代理。Reward Function 不完整，或 Reward Model 只在有限的人类偏好数据上训练时，Policy 持续针对它优化，就可能找到漏洞，甚至进入 RM 没见过的 OOD 分布，最终出现 Reward 很高但真实任务能力下降。

最后给治理方案：第一，采用多维、可验证的 Reward；第二，通过 KL Penalty、Reference Model、PPO Clipping 限制 Policy Drift；第三，用 Learning Rate、Gradient Clipping、Reward / Advantage Normalization 保证训练稳定；第四，建立独立 Evaluation，不能只看 Training Reward，要同时监控 Task Success、Human Eval、KL 和 Entropy。

用信号收束：如果 Reward 上升，但 Task Success 下降，同时 KL 快速升高、Entropy 快速降低，我会重点怀疑模型正在过度优化 Reward，甚至发生 Reward Hacking 或 Policy Collapse。
