二、神经网络：一群会根据错题调整经验的数字助理#

2.1 一个神经元在做什么#

一个最简单的神经元可以拆成三步：

面积 x₁ 房龄 x₂ 地铁 x₃
× 权重
求和
Σwᵢxᵢ + b
→
激活函数
输出特征

公式写作：

h = activation(Wx + b)
  • x：输入特征。
  • W：每个特征有多重要，也就是权重。
  • b：偏置，让判断边界可以平移。
  • 激活函数：加入非线性，否则多层线性变换仍等价于一层线性变换。

2.2 为什么要堆很多层#

用“看房助理团队”理解：

  1. 第一层分别读取面积、房龄、位置等原始特征。
  2. 中间层把它们组合成“交通便利”“居住舒适”“性价比”等更抽象特征。
  3. 输出层给出“买”和“不买”的分数。
  4. Softmax 把分数变成和为 1 的概率。
生活类比

第一排助理整理事实，第二排助理形成判断，最后一排助理汇总结论。每层不只是重复上一层，而是在上一层特征之上继续组合。

2.3 损失函数：给模型的答案打分#

假设真实结果是“买”，模型预测：

流程 / 推演
买：0.85
不买：0.15

交叉熵损失会重点查看正确类别的概率：

正确类别为“买”
Loss = −log(0.85) ≈ 0.163

正确答案概率越接近 1，损失越小；概率越接近 0，惩罚越大。

2.4 反向传播：不是“反着运行”，而是分配责任#

前向传播负责得到预测，反向传播负责回答：这次错误，每个权重分别负多少责任？

流程 / 推演
前向：输入 → 隐藏层 1 → 隐藏层 2 → 概率 → 损失
反向：损失 → 输出层梯度 → 隐藏层 2 梯度 → 隐藏层 1 梯度

对于 Softmax 与交叉熵的常见组合，输出层误差非常简洁：

δ₃ = 预测概率 − 真实标签
[0.85, 0.15] − [1, 0] = [−0.15, 0.15]

每层可以记住两条机械规则：

流程 / 推演
当前层的权重梯度 = 前一层输出ᵀ × 当前层误差
前一层误差 = 当前层误差 × 当前层权重ᵀ × 激活函数梯度

最后由优化器更新：

流程 / 推演
新权重 = 旧权重 − 学习率 × 权重梯度

2.5 神经网络为什么能学习复杂规律#

  • 权重可以从数据中自动调整，不需要手写每条规则。
  • 激活函数让模型可以表示非线性关系。
  • 多层结构把简单特征组合成越来越抽象的特征。
  • 反向传播让数以亿计的参数都能获得明确的更新方向。

三、为什么需要 Transformer#

3.1 对语言模型来说，Transformer 是什么#

在 Decoder-Only 大语言模型中，可以把 Transformer 看成一个重复调用的函数：

已有 Token 序列 → 下一个 Token 的概率分布

例如：

流程 / 推演
输入：“中国的首都是”
模型输出：北京 0.92、上海 0.03、南京 0.01、其他 0.04

选出一个 Token 后，将它追加到序列，再预测下一步：

流程 / 推演
“中国的首都是”       → “北京”
“中国的首都是北京”   → “。”

这叫自回归生成。

3.2 RNN/LSTM 解决了什么，又受限在哪里#

RNN 按顺序读取 Token：

流程 / 推演
Token₁ → Token₂ → Token₃ → Token₄

后一个位置依赖前一个位置的隐藏状态。LSTM 通过门控机制改善长期记忆，但仍有两个关键限制：

  1. 训练难以充分并行：处理第 4 个位置前，需要先算完前 3 个位置。
  2. 长距离路径较长：第 1 个 Token 的信息要连续传递很多步才能到达第 100 个 Token。

需要修正一个常见误解：RNN 并不是“只能一层”，它也可以堆叠多层。问题主要是序列方向上的递归依赖与长距离传播，而不是层数被限制。

3.3 Transformer 的关键改变#

Self-Attention 让每个位置可以直接读取其他位置的信息：

流程 / 推演
      ┌──────────────┐
Token₁  Token₂  Token₃  Token₄
  ↖      ↑  ↗   ↙      ↘
每个位置都能按需要与其他位置建立联系

带来的好处：

  • 训练时可以并行处理一个序列里的多个位置。
  • 任意两个位置之间只需要一次注意力连接。
  • 多头注意力能同时学习指代、修饰、语法、位置等不同关系。
  • 同一套结构可以扩展到文本、图像、语音和多模态。

但也要准确理解：

  • Decoder-Only 模型在训练时可以并行计算多个位置。
  • 在普通自回归推理时，仍需要一个 Token 接一个 Token 生成。
  • 标准全注意力的计算和显存开销会随序列长度近似按 n² 增长。

3.4 为什么不能简单说“Transformer 就是预测下一个 Token”#

预测下一个 Token 是 Decoder-Only 语言模型的典型训练目标，但 Transformer 本身是一种通用架构：

  • BERT 类 Encoder-Only 模型擅长文本理解和表示学习。
  • T5 类 Encoder-Decoder 模型擅长翻译、摘要等序列到序列任务。
  • Vision Transformer 可以处理图像 Patch。

因此更准确的说法是：Transformer 用注意力处理序列，而大多数生成式 LLM 使用 Decoder-Only Transformer 预测下一个 Token。

四、Transformer 输入：Token、Embedding 与位置#

4.1 Tokenization：模型处理的不是“词”，而是 Token#

文本会先被分词器拆成 Token：

流程 / 推演
what's that
→ ["what", "'s", "that"]

中文也不一定严格按单字或词语拆分。具体结果由模型使用的词表和分词算法决定。

每个 Token 会被映射成一个整数 ID：

流程 / 推演
["我", "喜欢", "苹果"] → [315, 928, 1426]

ID 只是查表编号，1426 并不比 315 “语义更大”。

4.2 One-hot、ID 与稠密 Embedding#

表示方式 直觉 能否表达相似性
Token ID 词表里的页码 不能，数字距离没有语义
One-hot 只有对应位置为 1 的超长向量 不同词彼此正交
Dense Embedding 几百到几千维的连续向量 可以在训练中形成语义空间

ID 加 Embedding 表，本质上就是查表：

流程 / 推演
Token ID 1426
→ 取 Embedding 矩阵第 1426 行
→ 得到一个 d_model 维向量

4.3 为什么同一个词需要上下文#

比较：

流程 / 推演
我喜欢吃苹果。
我喜欢用苹果电脑。

进入模型时，两个“苹果”会查到相同的基础 Token Embedding；经过多层 Attention 后：

  • 第一句的“苹果”会更多吸收“吃”的信息，靠近水果语义。
  • 第二句的“苹果”会更多吸收“用、电脑”的信息，靠近品牌语义。

所以更准确的说法是：初始 Embedding 可以相同，上下文化后的隐藏向量应该不同。

4.4 为什么需要位置编码#

Self-Attention 本身主要根据内容计算相关性，并不知道 Token 的先后顺序。如果没有位置信息：

流程 / 推演
“我爱你” 与 “你爱我”

会包含相同的一组词，模型很难仅靠词向量区分谁在前、谁在后。

因此模型把词义和位置信息组合起来：

最终输入表示 = Token Embedding + Position Information

原始 Transformer 使用正弦/余弦位置编码；现代 LLM 还常使用 RoPE 等相对位置信息方案。位置方案不同，但目标相同：让模型知道顺序和距离。

我词义向量+位置 0
爱词义向量+位置 1
你词义向量+位置 2

5.1 Q、K、V：同一个 Token 的三种工作身份#

先纠正一个容易混淆的说法：模型通常处理的是 Token，不一定刚好等于一个完整的中文“词”。每个 Token 在当前层都有一个隐藏向量 Hᵢ，再经过三组不同的可学习矩阵，得到 Q、K、V。

Token 当前隐藏向量 Hᵢ这个位置此刻拥有的全部数字化信息
→
QHᵢ × WQ：我想从上下文找什么？作为提问方使用
KHᵢ × WK：别人可以怎样匹配我？作为检索索引使用
VHᵢ × WV：别人找到我后，我贡献什么？作为真正传递的内容使用
Q = HWQ　　K = HWK　　V = HWV
来源相同，变换矩阵和工作职责不同；WQ、WK、WV 都由训练学出
名称 直觉问题 图书馆类比
Query（Q） 我现在想找什么？ 读者提出的检索问题
Key（K） 我能被怎样找到？ 每本书的索引标签
Value（V） 我真正携带什么内容？ 书中的实际内容

每个 Token 都同时有自己的 Q、K、V#

句子 / 我 喜欢 吃 苹果
“我”   → Q我、K我、V我
“喜欢” → Q喜欢、K喜欢、V喜欢
“吃”   → Q吃、K吃、V吃
“苹果” → Q苹果、K苹果、V苹果

当位置 i 更新自己时，它拿自己的 Qᵢ 去匹配所有允许看到的位置的 Kⱼ。匹配分数越高，就越多地读取那个位置的 Vⱼ。所以 Q/K 决定“找谁”，V 决定“拿什么”。

V 里面具体是什么：不是“苹果”两个字#

V苹果 是一串浮点数，例如教学上可以虚构成 [0.8, 0.2, -0.5, …]。它是“苹果在当前层、当前语境下准备传给其他位置的一包特征”，不是字符串，也不是从词典复制出来的解释。

我喜欢吃苹果后面层的隐藏状态可能已经吸收“吃”等上下文，因此 V 更偏向水果、食物、动作对象等信息。
V苹果（水果语境）
苹果发布了新手机上下文不同，后面层的隐藏状态可能更偏向公司、品牌、产品发布等信息。
V苹果（公司语境）

这些中文标签只是方便理解。真实模型里，一个概念通常分散在很多维度中，一维也可能参与多个概念，不能简单认定“第 7 维就是水果”。第一层的 V 主要来自 Token 初始表示和位置信息；越往后，V 越可能包含前面层已经汇总的上下文。

为什么 Q、K 计算匹配时不用 V？#

数据库类比

Q 是搜索条件，K 是索引，V 是查到后返回的记录。检索时先用索引判断该读哪条记录，不必让“索引”和“完整内容”承担同一份工作。

如果直接用 Q 匹配 V，那么 V 既要适合被检索，又要适合传递内容，两种目标会挤在同一个表示里。单独设置 K 后，模型可以分别学习“怎样被找到”和“找到后传什么”。在一次前向计算中 V 不直接决定权重，但训练误差仍会同时更新 WQ、WK 和 WV。

从 Q/K/V 到输出，完整走一遍#

以“吃”作为当前 Query 为例，注意力按下面顺序工作：

① 匹配Q吃 分别点乘 K我、K喜欢、K吃、K苹果
② 缩放与遮罩除以 √dₖ，并把不允许看的位置设为负无穷
③ Softmax把分数变成总和为 1 的关注比例
④ 汇总 V按比例加权 V我、V喜欢、V吃、V苹果

例如得到权重 [0.1, 0.1, 0.1, 0.7]，最终并不是把“苹果”这个词复制给“吃”，而是计算：

“吃”这个位置读回来的上下文
O吃 = 0.1V我 + 0.1V喜欢 + 0.1V吃 + 0.7V苹果
结果仍是一个向量，之后还会经过输出投影、残差、归一化和 FFN

完整计算可以写成：

  1. 用 Q · Kᵀ 算匹配分数。
  2. 除以 √dₖ，避免维度大时点积过大。
  3. 应用 Mask，遮住不能看的位置。
  4. 用 Softmax 变成每行和为 1 的权重。
  5. 对 V 加权求和。
Scaled Dot-Product Attention
Attention(Q,K,V) = softmax(QKᵀ / √dₖ) · V

这条公式里的乘法分成两种作用：QKᵀ 是“计算路由比例”，最后的 ·V 才是“按比例搬运内容”。

5.2 注意力矩阵的行和列表示什么#

对于长度为 8 的序列，单个注意力头会得到一个 8 × 8 权重矩阵：

  • 第 i 行：位置 i 作为 Query，正在找信息。
  • 第 j 列：位置 j 作为 Key，等待被关注。
  • A[i,j]：位置 i 从位置 j 读取信息的比例。
  • 每一行经过 Softmax 后总和为 1。
  • 矩阵通常不对称：A[i,j] 不必等于 A[j,i]。

例如句子“远方有棵苹果树，它非常美丽”中，“它”可能高权重关注“苹果树”，帮助完成指代消解。

形状为什么会变成 n × n？#

假设序列有 n 个 Token，每个头的 Q/K 维度是 dₖ，V 维度是 dᵥ：

张量形状
Q              [n, dₖ]
Kᵀ             [dₖ, n]
Q × Kᵀ         [n, n]    ← 每个 Query 对每个 Key 的分数
Attention × V  [n, dᵥ]   ← 每个位置汇总后的内容

n × n 表示每个位置都可能和每个位置建立关系，也解释了标准全量 Attention 的计算和显存成本为何会随序列长度近似按 O(n²) 增长。

5.3 可操作实验：上下文如何改变“苹果”的关注对象#

可操作实验

切换语境，观察“苹果”向谁取信息

5.4 多头注意力：同一句话，同时用多套匹配方式#

一个注意力头只有一套 Q/K/V 投影，相当于只用一套标准判断“谁该关注谁”。Multi-Head Attention 会为每个头准备自己的 WQ、WK、WV，让它们并行学习不同的匹配和内容提取方式。

流程 / 推演
头 1：可能偏向指代关系
头 2：可能偏向相邻修饰
头 3：可能偏向语法结构
头 4：可能偏向长距离依赖
Head 1Q¹K¹V¹独立算 Attention¹
Head 2Q²K²V²独立算 Attention²
Head 3Q³K³V³独立算 Attention³
Concat拼接所有头的结果× Wₒ重新融合回模型隐藏维度

例如隐藏维度 d_model = 512、头数 8，常见安排是每个头处理 64 维，最后将 8 × 64 维拼回 512 维。因此“多头”通常是把总表示空间拆给多个观察视角，不是复制出 8 个完整 Transformer。

同一个“苹果”在不同头里会有不同的 Q、K、V：某个头可能更容易建立“吃 → 苹果”的动作对象关系，另一个头可能更关注位置或修饰关系。每个头不仅关注权重可能不同，传递的 V 也不同。

“每个头专门负责某种语法”只是帮助理解的类比。真实模型中，头的功能可能混合、重叠，也会随层次变化。

多头 Attention 和堆很多层，是一回事吗？#

不是，但它们经常嵌套在一起。多头解决“一轮里从几个角度看”，多层解决“连续加工多少轮”。

多头：同一层内并行

多个头读取同一份本层输入 Hˡ，各自使用一套 Q/K/V 投影，同时观察不同关系。

头之间通常不能先后依赖；所有头算完后才拼接、融合。

多层：不同层前后串行

第 l+1 层读取第 l 层已经加工后的输出。

后一层看到的 Token 表示已经吸收了前一层建立的关系，因此可以继续组合和加工。

嵌套关系 / 每层内部有多个头
第 1 层 Transformer
  ├─ Head 1 ┐
  ├─ Head 2 ├─ 并行观察 → Concat × Wₒ → FFN
  └─ Head 3 ┘
                     ↓ 第 1 层输出成为第 2 层输入
第 2 层 Transformer
  ├─ Head 1 ┐
  ├─ Head 2 ├─ 再观察已经上下文化的信息 → FFN
  └─ Head 3 ┘
对比多头 Attention多层 Transformer
工作方式同一层内并行层与层之间串行
读取什么多个头读取同一层输入下一层读取上一层输出
主要增加什么一轮中的观察视角连续加工和关系组合的步骤
生活类比同一轮会议里的多位观察员根据上一轮结论继续开下一轮会议

例如第一层的多个头可能分别建立“放—苹果”“放—桌子”“它—候选名词”等基础联系。第二层的多个头读取这些已经更新过的表示，再结合“晃”等信息继续判断指代。多头不能代替多层，因为并行的头没有机会先读取其他头刚刚产生的结果；下一层才有这个机会。

并行与串行
Headsˡ = {head₁(Hˡ), …, headₕ(Hˡ)}
同层多个头共享本层输入；Hˡ⁺¹ = Layerˡ(Hˡ)，下一层依赖上一层输出

5.5 Causal Mask：生成时不能偷看未来#

Decoder-Only 模型训练时，会一次输入整段 Token。为了保持“只能根据过去预测未来”的因果约束，需要把未来位置遮住。

可操作实验

选择当前位置，看看它能看到谁

规则很简单：第 i 个位置只能看到 0～i，不能看到 i+1 之后的 Token。实现上通常在 Softmax 前把未来位置的分数设为负无穷，使其概率变成 0。

“它”的 Q 会包含后面的“红色”吗？#

看句子“我拿起苹果，它是红色的”。答案取决于模型的可见范围，不能只靠 Q 的类比判断：

Decoder-Only / GPT：看不到未来

处理“它”这个位置时，“红色”还在右边，Causal Mask 会把它挡住。因此此时的 Q 不会提前包含“红色”。“它”只能利用左侧的“我拿起苹果”等信息寻找可能指代的对象。

等处理到后面的“红色”时，该位置可以读取前面的“它”和“苹果”，再完成进一步判断。

Encoder-Only / BERT：可以双向读取

“它”能够关注左边的“苹果”和右边的“红色”。第一层初始 Q 仍主要来自“它”的初始表示；经过一层双向 Attention 后，新的隐藏状态吸收了两侧上下文。

下一层由这个新隐藏状态生成的 Q，就可能间接包含“红色”相关的语境信息。

“Q 是一个中文问题”只是拟人化解释。Q 的本体是一串数字，它能包含哪些信息，取决于当前层输入的隐藏状态，以及 Attention Mask 允许它看见哪些位置。

5.6 残差连接：保留上一版，只学习这一轮的修改量#

残差连接不是要求当前模块重新生成全部结果，而是把模块计算出的“变化量”加回输入：

Residual Connection
y = x + F(x)
x 是当前版本，F(x) 是这一轮修改量，y 是交给下一层的新版本

用“逐轮还原立方体灯箱”理解#

假设目标是一比一还原一个立体灯箱，你会经过很多轮调整：先搭结构，再修比例、透视、灯光、材质和边缘。这里有两个不同概念：

堆很多层：决定调整多少轮

下一轮总是读取上一轮已经完成的版本，继续做更细的组合和加工。

xₗ₊₁ = Layerₗ(xₗ)

残差连接：决定每轮怎样更新

保留当前成品，只提交本轮需要增加、减少或修正的变化量，不从零重做。

xₗ₊₁ = xₗ + Fₗ(xₗ)

1当前版本
结构已经正确+ 2比例调整
宽度 −2%+ 3光影调整
顶部亮度 +10%+ 4细节调整
边缘反光 +3%

“残差”更准确的意思是变化量，不只是增加内容。修改量可以为正，也可以为负：亮度可以调高，宽度也可以调小。

连续多层的增量更新
x₁ = x₀ + F₁(x₀)    # 第一轮：在初始版本上修改
x₂ = x₁ + F₂(x₁)    # 第二轮：基于第一轮结果继续修改
x₃ = x₂ + F₃(x₂)    # 第三轮：继续完善，而不是从零开始

在 Transformer 中加在哪里？#

一个 Block 通常在 Attention 和 FFN 外各有一条残差路径。以下用常见 Pre-Norm 形式简化表示：

Transformer Block
x₁ = x  + Attention(Norm(x))
x₂ = x₁ + FFN(Norm(x₁))
  • 第一条残差：保留 Token 原有信息，同时叠加从其他 Token 取回的上下文。
  • 第二条残差：保留交流后的表示，同时叠加 FFN 进一步加工出的特征。

为什么它让深层网络更容易训练？#

作用通俗理解对应机制
保存原信息已经做对的灯箱结构不必每轮重建输入 x 直接加回输出
只学增量当前层只需回答“这一轮改什么”模块学习 F(x)
传递梯度训练信号拥有一条不经过复杂模块的近路∂y/∂x = 1 + ∂F/∂x
支持堆深某层暂时没有有用修改时，可以接近原样通过让 F(x) ≈ 0

残差连接提供的是信息和梯度的直达路径，但不会独自解决所有稳定性问题；它通常需要和 LayerNorm、合适的初始化、学习率等机制配合。

会跳过某一层吗？先区分两种“跳过”#

效果上接近跳过

标准 Transformer 仍执行这一层。如果学到 F(x) ≈ 0，输出就接近输入，这一层对结果的修改很小。

计算仍然发生，所以不会因此自动节省推理时间。

计算上真正跳过

只有 LayerDrop、Stochastic Depth、Early Exit、动态深度或层裁剪等专门机制，才会不执行某些层。

这不是普通残差连接默认提供的能力。

后面的层还可能抵消前面层的部分调整，例如一层把某项特征提高，下一层又把它降低。这属于后续变换削弱了影响，不等于程序回退或删除了那一层。

情况这一层是否计算是否节省计算
普通残差，F(x) ≈ 0是否，只是效果接近原样通过
LayerDrop / Stochastic Depth训练时可随机不执行取决于训练与部署方案
Early Exit / 动态深度满足条件时不执行后续层可以
MoE Top-k层仍执行，但只运行少数专家节省未选专家的计算，不等于跳过整层
一句话：多层像多轮完善灯箱，残差连接像“上一版 + 本轮修改量”；它允许某层影响接近于零，但普通残差不会自动跳过这层计算。

5.7 LayerNorm：把每个 Token 的特征调回稳定尺度#

LayerNorm 会针对一个 Token 的隐藏维度做归一化，再使用可学习参数缩放和平移：

LN(x) = γ ⊙ (x − μ) / √(σ² + ε) + β

它与 BatchNorm 的关键区别：

LayerNorm BatchNorm
对单个样本的特征维归一化 对批次中同一特征归一化
不依赖 Batch 大小 依赖批次统计量
很适合可变长度序列 常见于卷积网络等场景

Pre-LN 与 Post-LN#

流程 / 推演
Post-LN：y = LN(x + F(x))
Pre-LN： y = x + F(LN(x))
  • 原始 Transformer 使用 Post-LN。
  • 许多现代深层 LLM 使用 Pre-LN 或其变体，因为梯度能更直接地沿残差路径传播。
  • 不能简单把所有模型归为同一种摆放方式，具体实现应查看对应模型结构。

5.8 FFN：Attention 交流之后，每个 Token 独立思考#

Self-Attention 负责 Token 之间交换信息，FFN 则对每个位置应用同一套非线性网络：

隐藏维度
d_model→ 升维 更宽的中间层
d_ff→ 激活 GELU / SiLU / SwiGLU→ 降维 输出维度
d_model

简化公式：

FFN(x) = W₂ · activation(W₁x + b₁) + b₂

为什么需要激活函数？如果只有连续的线性变换：

流程 / 推演
W₂(W₁x) = (W₂W₁)x

无论堆多少层仍可合并成一次矩阵乘法。激活函数打破这种线性合并，让模型具有更强表达能力。

5.9 堆叠多层后发生什么#

每个 Block 都重复“交流 + 加工”：

流程 / 推演
较浅层：局部搭配、词形、位置等基础模式
中间层：语法关系、指代、句子结构
较深层：更综合的语义与任务相关表示

这是一种整体直觉，不代表每一层都有严格固定的职责。最后隐藏状态通过线性输出层映射到词表大小的 logits，再由 Softmax 得到下一个 Token 的概率。

六、三类 Transformer 架构怎么选#

Decoder-Only 擅长生成

使用因果 Mask，只能看当前位置及之前的 Token。

代表：GPT、Llama、Qwen 等
Encoder-Only 擅长理解与表示

双向注意力，每个 Token 可以看到完整上下文。

代表：BERT、RoBERTa 等
Encoder-Decoder 擅长序列转换

Encoder 理解输入，Decoder 通过交叉注意力生成输出。

代表：T5、BART 等

6.1 Decoder-Only：只用左侧上下文继续写#

训练目标通常是预测每个位置的下一个 Token，使用三角形 Causal Mask 防止偷看未来。

适合：

  • 对话和文本续写
  • 代码生成
  • 通用大语言模型
  • 通过 Prompt 统一多种任务

6.2 Encoder-Only：整句话一起理解#

每个 Token 可以看到左右两边完整上下文，常使用 [CLS] 或池化后的句向量完成分类。

流程 / 推演
[CLS] 这 家 餐厅 很 好 [SEP]
  ↓
句子整体表示
  ↓
积极 / 中性 / 消极

适合分类、实体识别、语义匹配和向量表示等理解型任务。

6.3 Encoder-Decoder：一边读原文，一边生成目标#

以翻译为例：

流程 / 推演
Encoder：完整理解“远方有棵苹果树”
Decoder：[BOS] → There → is → an → apple → tree → [EOS]

Decoder 有两种注意力：

  1. Masked Self-Attention：读取已经生成的目标 Token。
  2. Cross-Attention：Query 来自 Decoder，Key/Value 来自 Encoder 输出。

Cross-Attention 让生成到 apple 时，可以重点读取源句中的“苹果树”。

6.4 快速选择表#

需求 更自然的架构 原因
聊天、续写、代码生成 Decoder-Only 自回归生成能力强
情感分类、实体识别 Encoder-Only 能双向读取完整句子
翻译、摘要、改写 Encoder-Decoder 输入理解与输出生成分工明确
通用指令模型 Decoder-Only 常见 用统一“继续生成”接口覆盖任务

七、注意力变体：MHA、MQA、GQA 与 MLA#

长文本推理时，模型需要缓存过去 Token 的 Key 和 Value，也就是 KV Cache。不同注意力变体的重要差别之一，就是 K/V 在多少个头之间共享。

7.0 为什么缓存 K/V，通常不缓存过去的 Q？#

自回归生成新 Token 时，当前新位置需要一份新的 Q，去查询所有历史位置的 K，并读取它们的 V。历史位置的 K/V 在生成后续 Token 时可以反复复用，因此值得保存；历史 Q 已经完成了当时那次查询，未来的新 Token 不会拿历史 Q 来发问。

生成第 t 个 Token
新位置：计算 Qₜ、Kₜ、Vₜ
查询：  Qₜ × [K₀, K₁, …, Kₜ]ᵀ
读取：  用权重汇总 [V₀, V₁, …, Vₜ]
缓存：  把 Kₜ、Vₜ 追加到 KV Cache，留给下一步复用

KV Cache 用显存换速度：避免每生成一个 Token 都重新计算全部历史 K/V，但缓存会随层数、序列长度、K/V 头数和每头维度增长。MQA、GQA、MLA 的重要工程动机之一，就是减少这部分缓存和带宽压力。

7.1 MHA：每个 Query 头都有自己的 K/V#

Multi-Head Attention 中，每个头都有独立的 Q、K、V 投影。

  • 表达能力强。
  • KV Cache 较大。
  • 是最经典的多头注意力形态。

7.2 MQA：所有 Query 头共享一组 K/V#

Multi-Query Attention 保留多个 Query 头，但让它们共享一组 K/V。

  • KV Cache 显著减小。
  • 推理带宽压力更低。
  • 共享过强可能影响部分表达能力。

7.3 GQA：若干 Query 头共享一组 K/V#

Grouped-Query Attention 是 MHA 与 MQA 之间的折中：

流程 / 推演
8 个 Query 头
→ 分成 2 组
→ 每组 4 个 Query 头共享一组 K/V

它通常能在模型质量和推理效率之间取得较好平衡。

7.4 MLA：把 K/V 信息压缩到低维潜在表示#

Multi-head Latent Attention 不是简单改变“几个头共享 K/V”，而是把 K/V 压缩为更小的潜在表示，在推理时缓存压缩结果，再恢复注意力需要的信息。

  • 目标同样是减少 KV Cache。
  • 实现方式和普通 MHA/GQA 不同。
  • 常和 RoPE 解耦、低秩投影等具体结构一起理解。

7.5 一张表看懂#

机制 K/V 组织方式 KV Cache 直觉
MHA 每个 Query 头独立 K/V 大 每个人都有自己的资料副本
MQA 所有 Query 头共享 K/V 最小 所有人共用一份资料
GQA 一组 Query 头共享 K/V 中等 每个小组共用一份资料
MLA K/V 压缩到潜在表示 较小 只保存压缩笔记，需要时再展开

八、MoE：不是所有专家都要同时上班#

8.1 MoE 到底替换了哪里#

在常见 Transformer MoE 中，通常把 Block 里的普通 FFN 替换成多个 Expert FFN：

Dense BlockAttention→一个 FFN
替换
MoE BlockAttention→Router + 多个 Expert FFN

MoE 通常不是用来替换 Attention，而是扩展 FFN 部分的参数容量。

8.2 用“专家会诊”理解 Router#

假设模型准备了四个专家：

流程 / 推演
专家 1：数学推理
专家 2：代码模式
专家 3：语言表达
专家 4：事实知识

Router 查看每个 Token 的隐藏向量，给专家打分，再选择 Top-k：

流程 / 推演
Token“积分” → 数学 0.62、代码 0.08、语言 0.10、知识 0.20
Top-2 → 数学专家 + 知识专家

被选专家分别处理这个 Token，最终输出按路由权重加权相加。

8.3 可操作实验：让不同 Token 选择专家#

可操作实验

选择一个 Token，观察 Top-2 路由

本次激活 数学专家 + 知识专家

Router 判断“积分”更需要数学推理，同时调用知识专家补充概念。

这些专家名称只是教学标签。真实模型的专家分工通常由训练自动形成，不一定能干净地解释为“数学专家”或“代码专家”。

8.4 Dense MoE 与 Sparse MoE#

方式 每个 Token 调用多少专家 结果
Dense / 基础混合 所有专家 计算量随专家数一起增长
Sparse MoE 只调用 Top-k 总参数很多，但单 Token 激活参数较少

Sparse MoE 的核心收益：在不让每次计算按总参数量同比增长的情况下，增加模型容量。

例如模型有 64 个专家，每个 Token 只选 Top-2，那么这个 Token 只执行其中 2 个专家，而不是 64 个全部执行。

8.5 Router 的四个步骤#

Python / PyTorch
# hidden_states: [token_count, hidden_dim]
router_logits = gate(hidden_states)          # 每个 Token 对每个专家的分数
routing_probs = softmax(router_logits, -1)  # 转成概率
weights, experts = topk(routing_probs, k=2) # 选 Top-2
weights = weights / weights.sum(-1, keepdim=True)

然后按专家收集 Token：

流程 / 推演
专家 0 收到：[Token 2, Token 7, Token 9]
专家 1 收到：[Token 0, Token 3]
专家 2 收到：[Token 1, Token 4, Token 6]
……

每个专家批量处理分配给自己的 Token，最后再把结果放回原位置并按权重合并。

8.6 形状怎么变化#

假设：

流程 / 推演
batch = 2
seq_len = 4
hidden_dim = 16
expert_number = 8
top_k = 2
数据 形状 含义
输入 x [2, 4, 16] 2 个样本，每个 4 个 Token
展平后 [8, 16] Router 按 Token 路由
Router logits [8, 8] 8 个 Token 对 8 个专家的分数
Top-k 索引 [8, 2] 每个 Token 选择 2 个专家
最终输出 [2, 4, 16] 恢复原始序列形状

Notebook 的测试使用 2 个专家并选择 Top-2，因此每个 Token 实际会调用全部专家；它能验证代码形状，但不能体现“稀疏激活”。要演示稀疏性，应让 expert_number > top_k，例如 8 选 2。

8.7 Shared Expert：公共知识始终处理，专项知识按需路由#

共享专家与路由专家同时存在：

Token 隐藏状态
始终执行Shared Experts吸收通用模式
Router 选择Top-k Routed Experts处理专项模式
相加 / 加权合并 → 输出

直觉上：

  • Shared Experts 负责所有 Token 都需要的公共能力。
  • Routed Experts 负责更细分、更有差异的模式。
  • 这样可以减少路由专家重复学习相同基础知识。

8.8 MoE 的难点不只是写一个 Top-k#

专家负载不均衡#

Router 可能把大量 Token 都分给少数专家，其他专家几乎没工作，称为专家坍塌。训练时通常需要负载均衡损失或其他路由约束。

Expert Capacity#

每个专家能处理的 Token 数有限。过多 Token 涌入同一专家时，需要容量系数、溢出策略或无丢弃路由设计。

跨设备通信#

专家往往分布在不同 GPU 上。把 Token 发给专家再收回结果会产生 All-to-All 通信，可能成为训练瓶颈。

路由稳定性#

Top-k 是离散选择，Router 的数值稳定、精度和训练策略都会影响最终效果。

总参数不等于激活参数#

MoE 可以拥有很大的总参数量，但一次前向只激活少量专家。比较模型成本时，应同时看总参数、激活参数、显存、通信量和实际吞吐。

8.9 Notebook 示例代码需要注意的简化#

Notebook 很适合学习形状和路由流程，但不应直接视为生产级 MoE：

  1. BasicMOE 直接把 Gate 线性层输出当权重，最好先经过 Softmax，否则可能出现负权重且权重和不为 1。
  2. return output.squeeze() 可能在 Batch 为 1 时误删 Batch 维，通常应只压缩明确的维度，例如 squeeze(1)。
  3. expert_number=2, top_k=2 会选择全部专家，不具备稀疏性。
  4. 示例没有包含负载均衡辅助损失、容量管理和分布式专家通信。
  5. 真实专家通常是带激活函数的 FFN/MLP，而不只是一个线性层。

更接近直觉的基础专家：

Python / PyTorch
class Expert(nn.Module):
    def __init__(self, hidden_dim, intermediate_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(hidden_dim, intermediate_dim),
            nn.SiLU(),
            nn.Linear(intermediate_dim, hidden_dim),
        )

    def forward(self, x):
        return self.net(x)

九、完整推理流程：一个 Token 怎样穿过 Transformer + MoE#

假设用户输入：

流程 / 推演
“请用 Python 写一个快速排序”

一次简化推理流程：

  1. Tokenizer：文本拆成 Token，并映射成 ID。
  2. Embedding：每个 ID 查到词向量，并加入位置信息。
  3. LayerNorm：把当前隐藏状态调整到稳定尺度。
  4. Self-Attention：当前 Token 从之前的 Token 读取上下文。
  5. 残差连接：保留 Attention 前的信息并叠加新信息。
  6. Router：每个 Token 根据隐藏状态选择 Top-k Expert。
  7. Expert FFN：被选专家分别处理 Token。
  8. 加权合并：按 Router 权重合并专家结果。
  9. 残差连接：叠加 MoE/FFN 之前的隐藏状态。
  10. 重复多层：逐层形成更丰富的上下文表示。
  11. 输出层：映射成整个词表的 logits。
  12. 采样：经过温度、Top-k 或 Top-p 等策略选出下一个 Token。
  13. 继续生成：把新 Token 加入上下文，重复上述过程。
Transformer + MoE 的本质：Attention 决定“从上下文哪里取信息”，Router 决定“交给哪些 FFN 专家加工”，输出层决定“下一个 Token 有哪些可能”。

十、常见误区#

误区 1：Attention 权重就是模型完整的思考过程#

Attention 权重只表示某一层、某一头的加权关系。模型输出还受到 Value、输出投影、FFN、残差和后续层影响，不能把一张注意力图等同于完整解释。

误区 2：Transformer 彻底解决了串行计算#

训练阶段能并行处理多个位置，但自回归推理仍需逐 Token 生成。KV Cache 避免重复计算过去状态，却不能取消先后依赖。

误区 3：模型层数越深，效果一定越好#

更深网络增加容量，也增加优化难度和计算成本。残差、归一化、初始化、学习率与数据质量共同决定深层模型是否有效。

误区 4：每个注意力头都有清晰固定的工作#

有些头会形成可观察模式，但头之间可能冗余、协作或随层变化，不能强行给所有头贴上稳定的人类标签。

误区 5：MoE 每次都会运行全部参数#

Sparse MoE 的核心正是按 Token 激活 Top-k 专家。总参数很多，但每次激活的专家参数只是其中一部分。

误区 6：MoE 专家天然会均匀分工#

如果没有合适的均衡策略，Router 可能偏爱少数专家。专家分工是训练结果，需要额外机制维护负载和稳定性。

误区 7：V 就是把原来的词复制过去#

V 是当前层从隐藏状态投影得到的数字向量。Attention 汇总的是多个 V 的加权和，不是复制字符串。后面层的 V 还可能包含之前各层已经吸收的上下文。

误区 8：Q 能提出一句明确的中文问题#

“Q 在问什么”只是帮助理解的拟人化表达。Q 实际是一串数字；它包含的信息来自当前隐藏状态，并受到层数、位置编码和 Mask 可见范围约束。

误区 9：多头等于多个完整模型各想一遍#

多个头是同一层内部的多个较小表示子空间。它们各自计算 Attention，输出拼接后再由 Wₒ 融合，不是多个独立大模型投票。

误区 10：增加头数和增加层数是一回事#

头数增加的是同一轮中的并行观察视角，层数增加的是前后依赖的计算步骤。多个头先合并，完成本层 Attention 和 FFN 后，结果才交给下一层；两者作用不同，不能互相等价替换。

误区 11：残差连接会自动跳过没有用的层#

残差连接可以让某层学习接近零的修改量，使其效果接近原样通过，但这一层的 Attention 或 FFN 通常仍会计算。真正跳层并节省计算需要 LayerDrop、Early Exit、动态深度等额外机制。

最后只记住这八句话#

  1. 神经网络通过损失和梯度调整权重。
  2. Token ID 只是索引，Embedding 才是模型真正计算的向量。
  3. 位置信息让 Attention 知道顺序和距离。
  4. Q 与 K 决定关注比例，V 提供真正汇总的内容。
  5. Attention 负责 Token 间交流，FFN 负责逐 Token 加工。
  6. 残差和归一化让深层 Transformer 更容易训练。
  7. Decoder-Only 用 Causal Mask 逐 Token 生成。
  8. MoE 用 Router 为每个 Token 选择少数 Expert，以较低激活成本扩充参数容量。
